# 网关与模型评测工作台

面向网关接入、路由调整和模型资源验收，在本机采集性能与质量证据，帮助判断下一步应排查、复测还是人工复核。

包含网关压测、TPM（每分钟词元）压测、路由对照、质量评测、模型指纹，以及用于管理地址和密钥的常用连接模块。结论仅覆盖客户端观测；不自动证明供应商身份、内部容量或批准生产放量。

## 环境与启动

使用 Python（运行环境）3.11 或更新版本；前端检查需要 Node.js（脚本运行环境）20 或更新版本。

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
npm ci
make run
```

打开 [本机工作台](http://127.0.0.1:8666/)。安装完成后，也可以在访达里双击 `启动正式版.command`：它使用正式数据目录启动服务，就绪后自动打开浏览器；服务已在运行时可选择直接打开或重启，关闭终端窗口即停止服务。首次运行创建管理员；已有数据继续使用原账号。可用 `ROUTE_TEST_PORT`（监听端口）设置其他端口。默认只监听本机回环地址；部署到服务器见 [服务器部署](docs/deployment.md)。

版本以 `app_version.py` 为准，页面健康接口 `/health` 可查看当前运行版本。

一键启动会先检查解释器是否可用、实际版本是否与虚拟环境配置一致，以及必要依赖是否齐全；检查失败不会启动新服务或停止已有服务。可在项目目录执行 `bash 启动正式版.command --check`（只检查环境），不会加载账号、历史或凭据。

如果目录是从其他电脑或应用复制的，或者提示虚拟环境版本不一致，不要直接在旧目录上重复创建环境。先停止工作台，保留原环境后，用本机独立安装的解释器重建：

```bash
mkdir -p backups/runtime
mv .venv "backups/runtime/venv-$(date +%Y%m%d-%H%M%S)"
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
bash 启动正式版.command --check
```

这些操作只更换运行环境，正式数据和账号仍保留。若错误是 `Operation not permitted`（系统不允许操作）且指向桌面目录中的配置文件，还需核查“系统设置 → 隐私与安全性 → 文件与文件夹”中终端对桌面的访问权限；普通文件权限正常并不代表已有系统隐私授权。具体入口见 [Apple（苹果）文件访问说明](https://support.apple.com/zh-sg/guide/mac-help/mchld5a35146/mac)。启动文件不会自动更改系统隐私设置。

浏览器回归和性能压测会在 `artifacts/`（验证产物目录）写入截图、日志和逐请求证据；环境重建时也可能在 `backups/runtime/`（运行环境备份目录）留下旧虚拟环境。它们都不属于代码交接内容，可在确认不再需要本地证据后运行 `make clean-local`（清理本地产物）移除；该命令不会触碰 `data/`（正式运行数据）或 `backups/legacy-root/`（旧数据备份）。

已结束的测试可在详情顶部点击“再来一次”，沿用原参数新建独立任务，原记录保留。优先复用原地址对应的已保存密钥，缺失时补填；需要风险确认的目标仍须确认本次运行。旧记录的冻结配置无法恢复时会明确提示，避免以当前默认值替换原测试参数。

网关压测、压力对照、路由对照和模型指纹的新建默认值统一为**并发上限 20、RPM（每分钟请求数）100**，均可在创建时修改；路由对照按每侧计算。六个内置压力模板采用同样的默认值，阶梯从每分钟 100 请求起逐档增压，保留原条数及持续时间。新建抽屉重新打开时恢复默认值；历史记录“再来一次”继续沿用原冻结参数。命令行未指定速率时同样默认每分钟 100 请求。

要验证上游提示缓存，请在网关压测新建抽屉的第 2 步“请求内容”选择**缓存压测**；压力对照也在这里明确选择各组共用的请求内容。该配置档固定一段长前缀，只轮换末尾问题，不把请求编号、时间戳或随机值放进前缀；命中率按 `cached_tokens > 0`（缓存词元大于零）的请求数 ÷ 总请求数计算，缺失 `usage`（用量）按未命中计入分母并单独标记。命令行执行器对应 `--profile cache`（缓存请求配置），并默认请求用量。

快速模板仅填充压力计划，不改变请求内容、连接、模型和名称；先选缓存压测还是先选模板，结果一致。各压力模式保留各自的参数草稿，手动调整后会退出模板选中状态。已结束任务先显示结果和失败线索，缓存统计口径、延迟明细与执行记录按需展开；“仅异常”筛选只覆盖页面上的最近请求，完整记录通过页底下载。

质量评测保留单题串行、双资源逐题交替的冻结协议，不增加压力参数；TPM（每分钟词元）模块继续按目标和校准耗时估算并发与连接池容量。模型指纹的速率纳入冻结协议，旧参考没有速率字段时仍按其原协议复测，不补写新默认值。

新建页先选择连接与模型，再填写测试范围。选择可用的常用连接后，地址与密钥默认收起，可按需展开编辑；手动连接保持展开。压力模板和低频高级配置默认收起，质量评测的原始记录开关也移入折叠区。

运行中的停止操作放在详情顶部，进入收尾后会显示当前状态；结束后同一位置提供“再来一次”。质量评测先看结论与建议，再按需展开完整计数和方法；指纹样本点击“查看证据”，集中查看原文、用量和时间。复测弹窗的确认按钮固定在底部，提交失败时保留输入供修正。

窄屏下六个模块入口完整显示在顶部，诊断、存储和主题工具在页面标题旁；记录栏可点击“收起”，为详情腾出空间。逐请求宽表在自身区域内横向滚动，展开时间会将证据滚入可视区；实时刷新保留当前阅读位置。浅色和深色遵循同一操作布局。

## 时间记录与核查

所有测试模块都会记录任务和逐请求时间，无需开启原始输入输出记录。新时间记录和界面统一使用**新加坡时间，固定 UTC+08:00（协调世界时加八小时）**，保留完整日期和毫秒，不跟随浏览器或服务器所在时区；耗时仍由单调时钟测量。

结构化时间示例为 `2026-10-16T08:12:36.245+08:00`，时区标识为 `Asia/Singapore`（亚洲／新加坡）。旧记录中的协调世界时或其他带时区时间，在查看与结构化报告导出时换算为同一真实时刻的新加坡时间；不批量改写旧原始文件。缺失或未写明时区的旧时间保持“未记录”，不猜测其原时区。

1. 打开测试详情，展开“时间记录”，查看创建、执行开始、请求停止、停发、结束及发现中断时间。压力对照的停发与收尾需进入对应实验组查看。
2. 在最近请求、路由逐条统计、质量题目中展开“查看时间记录”；指纹样本先点击“查看证据”。按任务编号、请求编号及侧别或资源核对计划、入队、实际开始、首字、结束和耗时。质量评测使用历史参考时，其逐题时间属于原采集，不是本轮的新请求。
3. 下载或导出对应结果，保留完整已落盘证据。网关和路由发生参数兼容重发时，每次真实尝试的时间也会保存；未开启正文记录不影响时间核查。

命令行运行时，除请求结果文件外，还会生成 `<out>.task.json`（输出文件旁的任务时间记录）；例如结果为 `run.jsonl`（逐行结果），旁边保留 `run.jsonl.task.json`（任务时间记录）。任务开始先写一次，结束时原子更新，核查时应一起保留。

“未记录”不等于零耗时或未发送；非流式请求没有可观测的首字时间。进程被强制结束时只能保留此前已落盘的证据；服务重启只记录发现中断时间，不把重启时刻补成请求结束时间。各模块任务执行耗时包括内部处理；TPM（每分钟词元）还包括等待正式确认，正式发压时长须看其阶段记录。所有时间都是客户端观测，跨机器对比仍需核对时钟偏差。完整字段和口径见 [指标口径](docs/metrics.md#全模块时间记录)。

## 默认思考模型的指纹采集

官方 `glm-5.3-flash`（模型名）不能关闭思考：在新建页的“回答协议与接口适配”中选择“智谱：保留思考”（其他接口选择其对应协议），核对每请求 4096 词元（含思考）的硬上限和全计划预算，再确认采集。默认直接回答协议仍为 16 词元，不自动扩容或重试；保留思考需要独立参考，目前只做探索性分布对照。仅支持明确兼容所选参数的接口，4096 不保证所有模型都能完成。具体参数、失败处理和来源见 [模型指纹使用说明](docs/模型指纹使用与方法.md#默认思考模型怎样测试)。

## 数据与凭据

- 新安装使用 `data/`；`ROUTE_TEST_DATA_DIR`（运行数据目录）可指定其他绝对路径。
- 老安装仍可读取项目根目录的数据。停止服务后运行 `.venv/bin/python tools/migrate_data.py`，校验复制成功后自动切换到 `data/`。原文件保留，不覆盖不同内容，不自动恢复未完成请求。
- 迁移完成后，可运行 `.venv/bin/python tools/migrate_data.py --archive-originals backups/legacy-root/manual-01`（归档旧副本；每次指定新的备份目录）把根目录旧文件收拢到 `backups/legacy-root/`（旧根目录备份）；逐文件校验并保存恢复清单，不合并旧记录，也不覆盖当前数据。源文件仍被进程使用时拒绝归档。
- 历史索引按记录写入 SQLite（嵌入式数据库）；质量评测逐题证据独立保存，旧索引只用于首次导入。
- 密钥通过系统安全存储保存，无法安全保存时明确提示；常用连接保存失败会保留表单供重试。
- 在“常用连接”中给请求地址和密钥取名保存；新建各类测试时可直接选择，仍可手动输入。同一地址可以保存多个名称和不同密钥。名称与地址保存在运行数据目录的 `connections.json`（连接配置文件），密钥单独存入本机凭据库；普通列表读取不返回密钥，编辑时可主动点击眼睛核对。
- 模型指纹手动输入的密钥只在本次运行内存中使用；选择常用连接时，服务端按连接编号取回密钥。
- 会话服务端最长 7 天、闲置 12 小时失效；重启可保留有效登录。退出后令牌立即作废。

## 检查命令

```bash
make test       # 编译、后端回归、前端逻辑、界面规则
make coverage   # 核心模块覆盖率门槛
npx playwright install chromium
make e2e        # 真实页面、临时账号、本机模拟接口
make benchmark  # 有限的本机请求引擎基线
make benchmark-tpm # 长输入流式模拟、完整工作台与浏览器联合验证
```

排查本机调度抖动可运行 `.venv/bin/python tools/benchmark_tpm.py --browser --diagnostics`（带浏览器及耗时探针的完整本地阶梯）。探针不改变负载或垃圾回收设置，额外证据位于本轮产物的 `runtime-probe.json`（运行耗时记录）；正式比较请同时保留关闭探针的结果。全部模拟用量均不代表真实上游容量，详见 [验证记录](docs/tpm-validation.md)。

若完整探针下未复现常态波动，可用 `--sparse-diagnostics`（稀疏诊断）替代 `--diagnostics`（完整诊断）：每 32 次睡眠、请求入口和选择器调用抽样一次，回收回调仍全量；分位范围只代表样本，不代替原精确统计和验收。普通联测保存 `observation.json`（阶段观测），包含原内存采样点及前后时钟，便于区分发压、收尾与报告。系统校时可能使时间证据检查失败，保留原失败轮，不自动校时或豁免。

浏览器测试只使用合成数据；设置 `CHROME_PATH`（浏览器路径）可选择已有浏览器。开发验证不需要真实上游密钥。持续集成在推送与合并请求时运行相同检查。

## 文件与产物目录

| 目录 | 用途 |
|---|---|
| `data/`（正式数据） | 账号、配置、历史索引、压测与质量证据；路由证据在其中的 `results/`（结果目录），指纹证据在 `fingerprint_data/`（指纹数据目录） |
| `artifacts/tests/`（后端回归产物） | 每轮独立目录，保留测试日志和结果摘要；合成运行数据在回归结束后清理 |
| `artifacts/browser/`（浏览器回归产物） | 按运行批次和测试套件分目录，集中保存截图、页面、服务日志与合成数据；既有截图收拢到其中的 `legacy/`（旧产物） |
| `artifacts/coverage/`（覆盖率产物） | 覆盖率数据库与各类报告；既有报告保存在其中的 `legacy/`（旧产物） |
| `artifacts/code-quality/`（代码质量验收） | 已交付的优化基准、页面比对和验收记录 |
| `backups/legacy-root/`（旧根目录备份） | 按批次保留已迁移的旧文件和恢复清单，独立于正式数据 |
| `tests/`（测试代码）、`tools/`（开发工具）、`docs/`（文档）、`static/`（界面资源）、`deploy/`（部署配置） | 版本管理中的项目文件，运行产物不得写入这些目录 |

后端回归统一通过 `make test`（完整检查）或 `.venv/bin/python tools/run_tests.py`（隔离回归入口）运行；入口在导入服务前设置独立数据目录并关闭系统凭据访问，覆盖率检查也使用此入口。不要绕过入口直接发现整套测试。

`TEST_ARTIFACT_DIR`（后端回归输出根目录）和 `UI_ARTIFACT_DIR`（浏览器回归输出根目录）可覆盖产物位置，每次仍创建独立批次目录。浏览器全套使用 `npm run e2e:full`（完整浏览器回归），单套使用 `make e2e`（浏览器基础回归）。`data/`（正式数据）、`artifacts/`（验证产物）、`backups/`（本地备份）均不提交到版本管理。
