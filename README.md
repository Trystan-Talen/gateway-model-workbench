# 网关与模型评测工作台

面向网关接入、路由调整和模型资源验收，在本机采集性能与质量证据，帮助判断下一步应排查、复测还是人工复核。

包含网关压测、路由对照、质量评测、模型指纹，以及用于管理地址和密钥的常用连接模块。结论仅覆盖客户端观测；不自动证明供应商身份、内部容量或批准生产放量。

## 环境与启动

使用 Python（运行环境）3.11 或更新版本；前端检查需要 Node.js（脚本运行环境）20 或更新版本。

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
npm ci
make run
```

打开 [本机工作台](http://127.0.0.1:8666/)。安装完成后，也可以在访达里双击 `启动正式版.command`：它使用正式数据目录启动服务，就绪后自动打开浏览器；服务已在运行时可选择直接打开或重启，关闭终端窗口即停止服务。首次运行创建管理员；已有数据继续使用原账号。可用 `ROUTE_TEST_PORT`（监听端口）设置其他端口。默认只监听本机回环地址；部署到服务器见 [服务器部署](docs/deployment.md)。

版本以 `app_version.py` 为准，页面健康接口 `/health` 可查看当前运行版本。

已结束的测试可在详情顶部点击“再来一次”，沿用原参数新建独立任务，原记录保留。优先复用原地址对应的已保存密钥，缺失时补填；需要风险确认的目标仍须确认本次运行。旧记录的冻结配置无法恢复时会明确提示，避免以当前默认值替换原测试参数。

网关压测新建默认并发与基础调度速率均为 100。快速填入压力参数的六个内置模板也采用这两个默认值；阶梯从 100 起保留逐档增压，模板原条数及持续时间保持不变。

## 数据与凭据

- 新安装使用 `data/`；`ROUTE_TEST_DATA_DIR`（运行数据目录）可指定其他绝对路径。
- 老安装仍可读取项目根目录的数据。停止服务后运行 `.venv/bin/python tools/migrate_data.py`，校验复制成功后自动切换到 `data/`。原文件保留，不覆盖不同内容，不自动恢复未完成请求。
- 迁移完成后，可运行 `.venv/bin/python tools/migrate_data.py --archive-originals backups/legacy-root/manual-01`（归档旧副本；每次指定新的备份目录）把根目录旧文件收拢到 `backups/legacy-root/`（旧根目录备份）；逐文件校验并保存恢复清单，不合并旧记录，也不覆盖当前数据。源文件仍被进程使用时拒绝归档。
- 历史索引按记录写入 SQLite（嵌入式数据库）；质量评测逐题证据独立保存，旧索引只用于首次导入。
- 密钥通过系统安全存储保存，无法安全保存时明确提示；常用连接保存失败会保留表单供重试。
- 在“常用连接”中给请求地址和密钥取名保存；新建各类测试时可直接选择，仍可手动输入。同一地址可以保存多个名称和不同密钥。名称与地址保存在运行数据目录的 `connections.json`（连接配置文件），密钥单独存入本机凭据库；普通列表读取不返回密钥，编辑时可主动点击眼睛核对。
- 模型指纹手动输入的密钥只在本次运行内存中使用；选择常用连接时，服务端按连接编号取回密钥。
- 会话服务端最长 7 天、闲置 12 小时失效；重启可保留有效登录。退出后令牌立即作废。

## 检查命令

```bash
make test       # 编译、后端回归、前端逻辑、界面规则
make coverage   # 核心模块覆盖率门槛
npx playwright install chromium
make e2e        # 真实页面、临时账号、本机模拟接口
make benchmark  # 有限的本机请求引擎基线
```

浏览器测试只使用合成数据；设置 `CHROME_PATH`（浏览器路径）可选择已有浏览器。开发验证不需要真实上游密钥。持续集成在推送与合并请求时运行相同检查。

## 文件与产物目录

| 目录 | 用途 |
|---|---|
| `data/`（正式数据） | 账号、配置、历史索引、压测与质量证据；路由证据在其中的 `results/`（结果目录），指纹证据在 `fingerprint_data/`（指纹数据目录） |
| `artifacts/tests/`（后端回归产物） | 每轮独立目录，保留测试日志和结果摘要；合成运行数据在回归结束后清理 |
| `artifacts/browser/`（浏览器回归产物） | 按运行批次和测试套件分目录，集中保存截图、页面、服务日志与合成数据；既有截图收拢到其中的 `legacy/`（旧产物） |
| `artifacts/coverage/`（覆盖率产物） | 覆盖率数据库与各类报告；既有报告保存在其中的 `legacy/`（旧产物） |
| `artifacts/code-quality/`（代码质量验收） | 已交付的优化基准、页面比对和验收记录 |
| `backups/legacy-root/`（旧根目录备份） | 按批次保留已迁移的旧文件和恢复清单，独立于正式数据 |
| `tests/`（测试代码）、`tools/`（开发工具）、`docs/`（文档）、`static/`（界面资源）、`deploy/`（部署配置） | 版本管理中的项目文件，运行产物不得写入这些目录 |

后端回归统一通过 `make test`（完整检查）或 `.venv/bin/python tools/run_tests.py`（隔离回归入口）运行；入口在导入服务前设置独立数据目录并关闭系统凭据访问，覆盖率检查也使用此入口。不要绕过入口直接发现整套测试。

`TEST_ARTIFACT_DIR`（后端回归输出根目录）和 `UI_ARTIFACT_DIR`（浏览器回归输出根目录）可覆盖产物位置，每次仍创建独立批次目录。浏览器全套使用 `npm run e2e:full`（完整浏览器回归），单套使用 `make e2e`（浏览器基础回归）。`data/`（正式数据）、`artifacts/`（验证产物）、`backups/`（本地备份）均不提交到版本管理。
