# 架构与数据恢复

## 当前边界

这是多账号工作台，默认只监听本机；也可以作为小团队（约 10 人）的内部服务部署到单台服务器，见 [服务器部署](deployment.md)。账号用于访问控制和操作归属，所有成员共享同一批记录。对外监听时，首次初始化只接受服务器本机来源；经反向代理访问时，按可信代理配置识别真实来源 IP。当前不承诺重启后继续执行、多进程或多机同时调度。

`route_test_ui.py` 负责请求入口与任务协调；请求引擎、质量判分、路由对照、指纹协议和执行器各自独立。前端在 `static/index.html`、`app.css`、`app.js`、`actions.js` 与独立指纹文件中；设计变量统一在 `tokens.css`，共享组件结构由 `ui-kit.js` 生成，规则见 [设计系统](design-system.md)。

这次先拆分鉴权会话、凭据、历史存储、数据路径、版本和前端资源。任务协调器仍较大；进一步按模块拆路由是后续可独立评审的结构改动，不需要同时引入新框架。

## 状态存储

正式服务通过 `app_paths.py`（数据路径模块）统一确定数据目录，默认使用 `data/`（正式数据）；保留旧安装兼容，迁移标记完成后切换到专属目录。回归入口在导入服务前覆盖数据路径，禁止测试初始化或读取正式账户、历史与系统凭据。开发产物和旧副本按 [文件与产物目录](../README.md#文件与产物目录) 分开存放。

| 数据 | 存储与恢复方式 |
|---|---|
| 账号 | `accounts.json`；按文件状态缓存，账号变更立即重新读取 |
| 会话 | `sessions.sqlite3`；只保存令牌哈希，检查绝对有效期和闲置时间 |
| 常用连接 | `connections.json`（连接配置文件）；只保存编号、名称、地址和更新时间，密钥按独立连接编号存入系统凭据库 |
| 任务索引 | `task_index.sqlite3`；按记录更新，事务内处理删除，未变化记录不重写 |
| 网关证据 | `run_*.jsonl`；历史快照保留采集时统计，不补造测量 |
| 质量证据 | `quality_run_*.json`；索引不重复保存逐题回答和报告 |
| 路由证据 | `results/` 内两侧结果文件；索引保存两侧缓存隔离标记，便于事后核对 |
| 指纹证据 | `fingerprint_data/`；协议、样本和可信参考分开保存 |
| 运维 | `audit.db`、`events.jsonl`；不记录请求密钥 |

索引表将小摘要和恢复快照分列保存。摘要不含逐题证据；恢复快照保留冻结配置及已有统计。质量证据缺失时标明过期，不能把摘要当作完整证据。

历史写入的进程内摘要缓存以解析后的数据库绝对路径为键，避免同一数据库的路径别名各持有一份旧摘要。事务成功后更新缓存，失败时丢弃缓存；当前单进程写入边界保持不变。

容量汇总与孤儿文件识别复用一次目录扫描。指纹样本分页逐行验证全部证据以保持准确总数和损坏提示，只保留偏移量与页容量以内的候选，按索引及文件顺序稳定排序；额外内存随保留的候选量增长，深分页的收益小于首页，文件变化在下次读取时直接生效。

旧 JSON（结构化数据）索引仅导入一次，即使删除了新索引里的全部记录，也不会再次导入旧文件而“复活”已删除任务。原索引保留用于核对。

## 再来一次

已结束记录通过 `/repeats/prepare`（复测准备接口）检查冻结参数及凭据，再通过 `/repeats`（复测创建接口）生成独立记录。原任务、结果和文件保持不变；新任务重新执行风险预检，不继承上一次确认。命名连接必须同时匹配原连接编号与原地址，连接删除或地址变化时要求补填密钥，不能自动改用同地址的其他连接。

质量评测复用冻结题目与历史参考证据；指纹采集复用原协议；路由对照核对清单版本并生成新的两侧缓存隔离标记。旧记录缺少完整配置、题集指纹不匹配或参考证据不可用时明确拒绝复测，不补上当前默认值。

## 路由对照的缓存隔离

两侧跑同一份确定性清单，背后又常是同一批上游渠道；不隔离时，先到的一侧和上一次运行都会替后到的请求预热前缀缓存。执行器因此为每次运行的两侧各生成一个 12 位数字标记，放在每条提示词的最前面：同侧同段前缀逐字相同，照常命中；跨侧、跨运行从第一个字起不同，互不预热。每段第一条请求没有先行者，报告统计其命中，并用发送时间排除同段抢跑，剩余命中不少于 2 段且达到 10% 时，将缓存命中率差值降级为不可归因。

## 前端与请求策略

列表使用摘要，只带当前选中任务的完整详情。进入模块、切换筛选或删除记录后自动打开最新一条，详情区只有在筛选为空时显示空状态。支持 ETag（内容校验标记）复用；运行时短间隔刷新，空闲时 30 秒检查新增记录，隐藏窗口暂停刷新。数据未变化时不重绘，避免打断阅读。

压测任务直接生成记录栏摘要，不先计算详情再裁剪；完整详情对同一批样本只排序一次，保留原有分位数口径。前端筛选优先只处理当前记录集合，无法形成有效日期排序的旧记录沿用混合排序；质量指标单次遍历、单次排序，平均值仍按原请求顺序累加。各模块文本转义共用组件库实现，指纹重绘建立滚动区域索引以恢复阅读位置。

路由实时与最终报告复用侧汇总和未舍入分位点，显示值与差值保持原精度。命令行执行器同时等待生产者和工作协程；任一协程失败或外部取消时，取消并等待其余协程结束，再关闭输出文件和客户端，防止队列满时永久等待。

脚本执行策略只允许本站外部脚本；点击事件通过显式函数表委托，不执行属性中的代码。样式保留行内权限，以支持进度宽度等已有动态样式。

## 错误和凭据

内部异常只向浏览器返回通用信息与请求编号；日志保存异常类别和栈位置，不记录可能包含密钥的异常文本。浏览器状态变更请求检查来源和跨站元数据。

凭据通过 `keyring`（系统凭据库）的明确系统后端访问 macOS（苹果桌面系统）、Windows（微软桌面系统）、Linux（开放源代码操作系统）的安全存储。没有明文文件降级，也不把密钥放入子进程参数。参考：[凭据库官方文档](https://keyring.readthedocs.io/en/latest/)。
