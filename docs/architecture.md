# 架构与数据恢复

## 当前边界

这是多账号工作台，默认只监听本机；也可以作为小团队（约 10 人）的内部服务部署到单台服务器，见 [服务器部署](deployment.md)。账号用于访问控制和操作归属，所有成员共享同一批记录。对外监听时，首次初始化只接受服务器本机来源；经反向代理访问时，按可信代理配置识别真实来源 IP。当前不承诺重启后继续执行、多进程或多机同时调度。

`route_test_ui.py` 负责请求入口与任务协调；请求引擎、质量判分、路由对照、指纹协议和执行器各自独立。前端在 `static/index.html`、`app.css`、`app.js`、`actions.js` 与独立指纹文件中；设计变量统一在 `tokens.css`，共享组件结构由 `ui-kit.js` 生成，规则见 [设计系统](design-system.md)。

这次先拆分鉴权会话、凭据、历史存储、数据路径、版本和前端资源。任务协调器仍较大；进一步按模块拆路由是后续可独立评审的结构改动，不需要同时引入新框架。

## 状态存储

TPM（每分钟词元）模块按职责拆为 `tpm_service.py`（任务准入与接口）、`tpm_config.py`（配置与预估）、`tpm_corpus.py`（合成语料）、`tpm_usage.py`（用量和预算）、`tpm_engine.py`（异步发压）、`tpm_metrics.py`（精确增量实时统计）、`tpm_report.py`（全量统计基准与最终报告）。入口仅转发鉴权后的请求。沿用连接解析、会话、任务状态及历史索引；新增独占资源占位，覆盖校准、待确认及收尾，防止其他模块争抢发压资源。

逐请求证据通过有界写队列批量落盘；历史快照每秒保存，浏览器限频观察。创建请求编号与冻结方案摘要防止重复收费启动。恢复只读历史时把未结束任务标记中断；按原参数复测仍需新的两次确认。详见 [使用说明](tpm.md)。

实时统计只消费新增的完成记录：用量窗口采用结束时间索引及整数前缀和，开始速率采用时间索引，耗时采用精确有序分布。查询不再反复扫描和排序全部历史，支持乱序结束与墙钟回拨；窗口、百分位及未知值语义与全量基准一致。完成记录和在途移除在同一锁内发布，已发布记录保持不变。记录栏直接生成轻量摘要，不复制曲线和逐请求证据；详情和导出仍返回独立副本。最终报告继续读取原始逐请求记录，未改变判定协议。

浏览器观察使用显式 `/tpm/runs/<编号>/live`（实时展示）接口：在独立复制前仅投影最近请求表当前展示的字段，完整时间对象与缺失／空值／明确零的区别保留，带 `recent_requests_view=display-v1`（最近请求为展示视图第一版）标记。统计、预算和报告继续使用完整记录；原详情接口、历史索引、逐行证据与导出保持完整，不缓存或复用客户端答案。旧格式和逐次尝试等扩展记录保守保留完整字段，展示快照仍相互独立。观察频率保持原值。

`tpm_records.py`（完成记录存档）将完整完成记录编码一次，保留全部字段、原始用量和数值精度，复用相同编码正文增量落盘。内存仅保存最近 100 条展开记录，其余保存不可变编码字符串、按需还原，减少长期嵌套对象的垃圾回收扫描；不删除旧证据，不调整回收设置。实时统计即使一次落后超过 100 条也会精确消费冷记录；报告在停止发压并收尾后局部展开完整记录，不长期缓存展开副本。编码失败时保留已结算原记录、移除在途并立即停发，不能重复结算或假称已落盘；即使此前已有完整目标窗口，报告也保留原始数值并降为证据不足。

执行器为其拥有的响应流增加透传包装：底层关闭成功后释放内层流引用，打断 HTTPX（请求库）已关闭响应与绑定流的循环引用，避免长请求正文一直留到循环回收。只使用公开流接口，不清改请求库私有字段、请求内容或记录证据；关闭异常或取消时保留原流引用，不用提前置位的关闭标志伪称清理完成。完整读取、原流上下文和原总超时上下文均正常退出后才记为成功，关闭失败的请求仍保留用量和费用，不能计入成功完成吞吐。自定义传输预先关闭的响应不是正常网络路径，不承诺它或其他异步生成器对象都能即时释放。

长语料同时保留按组预编码的请求片段，逐请求仅编码短变量并拼接，校准改变语料后重新生成；发送字节与原请求序列化一致，预算仍使用真实字节上界。`tpm_snapshot.py`（快照复制）优化常见内建容器的独立复制，保留共享引用、循环及未知类型的标准库处理。接口脱敏继续构造独立容器，仅有界缓存字段名规范化，不缓存凭据或安全判断结果。逐批证据写入与刷新合并为一次工作线程调用，刷新成功后才确认队列项；到达等待使用当前任务的超时上下文，保留即时停止唤醒，不改变固定时隙或补发规则。仅最后时隙距档末不足 2 毫秒时提前唤醒一次，再严格等到原计划时刻；发送前在池等待、编码及预算／摘要准备之后检查原档位截止，越界撤销未发送预留并记为遗漏。已发送请求继续使用原总超时收尾。

正式服务通过 `app_paths.py`（数据路径模块）统一确定数据目录，默认使用 `data/`（正式数据）；保留旧安装兼容，迁移标记完成后切换到专属目录。回归入口在导入服务前覆盖数据路径，禁止测试初始化或读取正式账户、历史与系统凭据。开发产物和旧副本按 [文件与产物目录](../README.md#文件与产物目录) 分开存放。

| 数据 | 存储与恢复方式 |
|---|---|
| 账号 | `accounts.json`；按文件状态缓存，账号变更立即重新读取 |
| 会话 | `sessions.sqlite3`；只保存令牌哈希，检查绝对有效期和闲置时间 |
| 常用连接 | `connections.json`（连接配置文件）；只保存编号、名称、地址和更新时间，密钥按独立连接编号存入系统凭据库 |
| 任务索引 | `task_index.sqlite3`；按记录更新，事务内处理删除，未变化记录不重写 |
| 网关证据 | `run_*.jsonl`；历史快照保留采集时统计，不补造测量 |
| TPM（每分钟词元）证据 | `tpm_run_*.jsonl`（逐行请求摘要）；同一历史索引保存配置、校准、曲线与报告，无完整长提示词或全文输出 |
| 质量证据 | `quality_run_*.json`；索引不重复保存逐题回答和报告 |
| 路由证据 | `results/` 内两侧结果文件；索引保存两侧缓存隔离标记，便于事后核对 |
| 指纹证据 | `fingerprint_data/`；协议、样本和可信参考分开保存 |
| 运维 | `audit.db`、`events.jsonl`；不记录请求密钥 |

索引表将小摘要和恢复快照分列保存。摘要不含逐题证据；恢复快照保留冻结配置及已有统计。质量证据缺失时标明过期，不能把摘要当作完整证据。

历史写入的进程内摘要缓存以解析后的数据库绝对路径为键，避免同一数据库的路径别名各持有一份旧摘要。事务成功后更新缓存，失败时丢弃缓存；当前单进程写入边界保持不变。

容量汇总与孤儿文件识别复用一次目录扫描。指纹样本分页逐行验证全部证据以保持准确总数和损坏提示，只保留偏移量与页容量以内的候选，按索引及文件顺序稳定排序；额外内存随保留的候选量增长，深分页的收益小于首页，文件变化在下次读取时直接生效。

旧 JSON（结构化数据）索引仅导入一次，即使删除了新索引里的全部记录，也不会再次导入旧文件而“复活”已删除任务。原索引保留用于核对。

## 时间证据链

`time_record.py`（时间规范化模块）统一生成任务和请求的 `timing`（时间记录）对象：采用固定 UTC+08:00（协调世界时加八小时）的毫秒新加坡时间，时间字符串以 `+08:00` 结尾，`timezone`（时区）为 `Asia/Singapore`（亚洲／新加坡）；耗时由单调时钟提供。它只归一化明确记录的值，不推导缺失时间。`run_timing.py`（任务时钟与历史适配模块）负责生命周期事件、线程安全的时间标记和旧证据映射；指纹与 TPM（每分钟词元）执行器按各自调度边界接入同一格式。

请求引擎在真实尝试的开始、收到首个正文、成功结束或失败退出时记录时间；调度器提供计划和入队时间。网关与路由允许的参数兼容重发以 `attempts`（尝试记录）保留各次时间，不覆盖首轮证据。时间摘要不依赖 `capture_raw`（原始正文记录），沿现有请求结果文件、质量逐题记录、指纹样本和 TPM（每分钟词元）增量写队列落盘；历史摘要、详情和导出均保留相应时间。

任务事件独立于请求事件记录，不能把创建当执行、把停发当收尾完成。压力对照容器只有协调生命周期，各实验组保留自己的请求时间和停发边界；不为容器编造独立网络时间。指纹时间属于证据元数据，不进入冻结采样协议或协议摘要，兼容原参考导入和对照。质量评测复用历史参考证据时，同步保留参考侧原逐题时间，不更新为本轮时间，不将其计作本轮新请求。

命令行在结果文件旁写 `<out>.task.json`（任务时间文件），开始先写入，结束通过临时文件和原子替换更新。异常终止时，最后持久化的开始信息仍可核查；缺少结束字段不能当作成功完成。

恢复时，已有时间对象直接规范化；旧协调世界时或其他带时区时间，按同一真实时刻转换为新加坡时间用于查看和结构化报告导出，原始历史文件不批量改写。无时区、缺失或无效时间保持未知，不以运行机器的本地时区猜测；旧记录只映射其明确记录的时间和耗时。未结束任务只增加 `interruption_detected_at`（发现中断时间），不以恢复时刻补 `ended_at`（结束时间），不自动恢复请求。进程被强制结束时，未落盘事件和未完成请求的结束时间无法恢复，只保留之前写入成功的证据。系统时钟用于事件定位，单调时钟用于排队、请求和收尾耗时；不同机器采用相同的新加坡时区不意味着时钟已经同步。字段定义及各模块停发边界见 [指标口径](metrics.md#全模块时间记录)。

## 再来一次

已结束记录通过 `/repeats/prepare`（复测准备接口）检查冻结参数及凭据，再通过 `/repeats`（复测创建接口）生成独立记录。原任务、结果和文件保持不变；新任务重新执行风险预检，不继承上一次确认。命名连接必须同时匹配原连接编号与原地址，连接删除或地址变化时要求补填密钥，不能自动改用同地址的其他连接。

质量评测复用冻结题目与历史参考证据；指纹采集复用原协议；路由对照核对清单版本并生成新的两侧缓存隔离标记。旧记录缺少完整配置、题集指纹不匹配或参考证据不可用时明确拒绝复测，不补上当前默认值。

## 路由对照的缓存隔离

两侧跑同一份确定性清单，背后又常是同一批上游渠道；不隔离时，先到的一侧和上一次运行都会替后到的请求预热前缀缓存。执行器因此为每次运行的两侧各生成一个 12 位数字标记，放在每条提示词的最前面：同侧同段前缀逐字相同，照常命中；跨侧、跨运行从第一个字起不同，互不预热。每段第一条请求没有先行者，报告统计其命中，并用发送时间排除同段抢跑，剩余命中不少于 2 段且达到 10% 时，将缓存命中率差值降级为不可归因。

## 前端与请求策略

列表使用摘要，只带当前选中任务的完整详情。进入模块、切换筛选或删除记录后自动打开最新一条，详情区只有在筛选为空时显示空状态。支持 ETag（内容校验标记）复用；运行时短间隔刷新，空闲时 30 秒检查新增记录，隐藏窗口暂停刷新。数据未变化时不重绘，避免打断阅读。

压测任务直接生成记录栏摘要，不先计算详情再裁剪；完整详情对同一批样本只排序一次，保留原有分位数口径。前端筛选优先只处理当前记录集合，无法形成有效日期排序的旧记录沿用混合排序；质量指标单次遍历、单次排序，平均值仍按原请求顺序累加。各模块文本转义共用组件库实现，指纹重绘建立滚动区域索引以恢复阅读位置。

路由实时与最终报告复用侧汇总和未舍入分位点，显示值与差值保持原精度。命令行执行器同时等待生产者和工作协程；任一协程失败或外部取消时，取消并等待其余协程结束，再关闭输出文件和客户端，防止队列满时永久等待。

脚本执行策略只允许本站外部脚本；点击事件通过显式函数表委托，不执行属性中的代码。样式保留行内权限，以支持进度宽度等已有动态样式。

## 错误和凭据

内部异常只向浏览器返回通用信息与请求编号；日志保存异常类别和栈位置，不记录可能包含密钥的异常文本。浏览器状态变更请求检查来源和跨站元数据。

凭据通过 `keyring`（系统凭据库）的明确系统后端访问 macOS（苹果桌面系统）、Windows（微软桌面系统）、Linux（开放源代码操作系统）的安全存储。没有明文文件降级，也不把密钥放入子进程参数。参考：[凭据库官方文档](https://keyring.readthedocs.io/en/latest/)。
