# 指标口径

## 全模块时间记录

网关压测、压力对照各实验组、路由对照、质量评测、模型指纹及 TPM（每分钟词元）统一保存 `timing`（时间记录）对象，版本为 1。时间点采用 ISO 8601（国际日期时间格式）的毫秒新加坡时间，固定偏移为 UTC+08:00（协调世界时加八小时），例如 `2026-10-16T08:12:36.245+08:00`；`timezone`（时区）固定为 `Asia/Singapore`（亚洲／新加坡）。耗时单位为毫秒，由单调时钟测量，不能用两个墙钟时间相减替代。

新记录、界面与结构化报告导出使用同一新加坡时区，不依赖浏览器或运行机器的本地时区。旧时间末尾的 `Z`（协调世界时标记）或其他明确偏移会按同一真实时刻转换，例如 `2026-10-16T00:12:36.245Z` 转为 `2026-10-16T08:12:36.245+08:00`。旧原始证据文件的直接下载保留原字节和原时间表示，以便校验；不批量改写旧原始文件。缺失、无时区或无效时间保持未知，不直接加八小时猜测来源。既有数值时间戳仍表示同一绝对时刻，单调时钟耗时及计费、评分统计不因时区变更而改变。

这些时间来自运行后端服务的客户端时钟，不是浏览器时间、上游收到请求的时间或商家计费时间。统一时区不代表不同机器的时钟已同步；跨机器核查需同时确认各自时钟偏差。系统校时可能使时间点前后倒置，但不应改变单调时钟耗时。

### 任务生命周期

| 字段 | 含义 |
|---|---|
| `created_at`（创建时间） | 本轮任务记录创建 |
| `started_at`（执行开始时间） | 获得执行资格并实际开始本轮工作；不等于点击创建 |
| `stop_requested_at`（停止请求时间） | 客户端收到人工停止或触发停止保护；正常跑完可为空 |
| `dispatch_ended_at`（停发时间） | 本轮不再启动新请求的边界；已发请求可继续收尾 |
| `ended_at`（结束时间） | 客户端完成本轮执行及本模块收尾；不证明上游已停止处理或计费 |
| `interruption_detected_at`（发现中断时间） | 服务恢复时发现原任务未正常结束；不是实际崩溃或完成时间 |
| `queue_ms`（任务等待毫秒） | 创建至开始执行的单调时钟间隔 |
| `elapsed_ms`（执行耗时毫秒） | 开始执行至结束，运行中可显示已观测时长；包括本模块内部处理。TPM（每分钟词元）任务还包括等待正式方案确认的时间，不能当作正式发压时长 |
| `drain_ms`（收尾耗时毫秒） | 停发边界至本模块结束的单调时钟间隔 |

正常结束时，网关、路由及命令行按最后一次实际请求尝试的开始记录停发边界；指纹按最后一条样本进入执行记录。TPM（每分钟词元）按阶梯停止调度记录，正式发压时间另见其阶段与档位记录。人工停止保留停发信号时间。不同模块收尾耗时需结合上述边界比较。

压力对照容器只协调实验组，没有独立网络请求；容器的创建、执行和结束时间与各子组分别记录，容器不虚构聚合停发或收尾时间。两侧路由、双资源质量评测也须结合侧别、资源和请求编号核查，不能只比较容器时间。质量评测复用历史参考时，参考侧逐题保留原采集时间，不代表本轮重新发送了这些请求。

### 逐请求时间

| 字段 | 含义 |
|---|---|
| `scheduled_at`（计划发送时间） | 调度器预定的发送时隙；没有固定时隙的请求为空 |
| `enqueued_at`（入队时间） | 请求进入本模块等待或准入流程的时间 |
| `started_at`（实际开始时间） | 本次真实请求尝试开始，随后可能仍需连接、写入及等待响应；不表示上游已收到 |
| `first_token_at`（收到首字时间） | 首次收到真实响应正文；心跳、空片段不计。非流式响应无法观测，保留为空 |
| `ended_at`（请求结束时间） | 成功完整结束，或失败、超时、取消在客户端结束；不等于成功 |
| `queue_ms`（排队等待毫秒） | 入队或准入开始至本次请求开始的单调时钟间隔 |
| `schedule_lag_ms`（调度延迟毫秒） | 实际请求开始相对计划时隙的延迟；无时隙时为空 |
| `ttft_ms`（首字耗时毫秒） | 本次请求开始至首次真实正文；非流式响应及未收到正文时为空 |
| `total_ms`（请求总耗时毫秒） | 本次请求开始至客户端结束；包含失败和超时耗时，不包含此前排队 |

网关、路由及命令行如发生已允许的参数兼容重发，`attempts`（尝试记录）保留每次真实尝试的序号、结果和时间；最终结果的时间不替代前一次尝试。它不会引入新的业务重试策略。TPM（每分钟词元）继续禁止正式发压时隐式降级重发。

`source`（来源）区分 `recorded`（已记录）、`partial`（部分已记录）和 `legacy`（历史映射）；已记录不表示每个可选阶段都可观测。未知值保存为 `null`（空值），与明确的零毫秒不同。旧记录只映射可确定的原字段，不用文件修改时间补执行时间，也不由开始加耗时倒推结束或首字。进程被强制结束时，只能保留此前已落盘的证据，不能补造尚未完成请求的结束时间。重启后保留已落盘证据和发现中断时间，未知结束时间仍为空，不恢复收费请求。

界面的“时间记录”和逐请求“查看时间记录”默认收起，展开后显示完整日期、新加坡时区及耗时；不需要开启 `capture_raw`（原始正文记录）。时间字段随历史、结果文件及对应导出保留；命令行另写 `<out>.task.json`（输出文件旁的任务时间记录），在开始时落盘、结束时原子更新。未出现结束字段只能说明缺少结束证据，不能推定请求没有发生或没有费用。

仅从旧逐条文件恢复时，不把首条请求开始当作任务创建、末条开始当作任务结束，也不把发送时间重建成完成吞吐曲线。质量评测的可读报告同时导出任务时间和逐题起止表。

## TPM（每分钟词元）模块

- 主口径为「完整 Token TPM（完整词元/分钟）」：最近 60 秒成功完整结束请求的完整输入加输出；缓存输入只计一次。未满 60 秒不外推。客户端完成时间与商家日志、限流或计费时间不保证一致。
- 计划时隙、实际开始、成功完成、失败、未发出、在途分别计数。固定到达调度错过时隙直接丢弃，不排队集中补发，不按失败自动追赶。
- 实时统计采用精确增量索引：最近 60 秒完成量、最近 10 秒实际开始速率按左开右闭窗口计算；首字和完整耗时百分位仍覆盖全部正式完成请求，使用原线性插值，不使用近似分桶。缓存未知值与明确为零保持区分。最终报告独立从逐请求证据核算。
- 校准与预热仅计费用。报告主窗口为目标档最后一个完整 60 秒发压区间，且只计该档发出的请求；收尾完成量不补足达标窗口。完整结束还要求流式结束信号及自然完成，流内错误和输出硬上限单独记录。
- 用量归一化保留普通输入、缓存读取、缓存写入、完整输入、输出、原始用量、来源与完整性。输入已含缓存时减出互斥分类，独立列出须用户确认协议。累计流式快照只替换，不相加。未知值不等于零。
- 「达到」必须原始值不低于目标；默认「接近」为至少 95%。成功率默认至少 99%、错过时隙不超过 1%，用量缺失、没有目标完整窗口或发压端受限时不给通过；持续积压和明显错误/延迟恶化阻止稳定结论。阈值运行前冻结。
- 费用分预计、用户报价下的已知费用、未结算预留；未知请求保留费用风险。收尾等待不额外按满载时间计费。连接池指标为客户端准入等待，传输库内部等待标为不可单独观测。

## 网关压测缓存与错误证据

- 网关单次压测和压力对照默认请求上游 `usage`（用量）字段。页面主指标“缓存命中率（请求）”按 `cached_tokens > 0` 的请求数 ÷ 总请求数计算；“缓存 Token（词元）命中率”作为辅助指标，按累计 `cached_tokens`（缓存词元）÷ 累计 `prompt_tokens`（输入词元）计算。没有缓存字段的请求按请求命中率视为未命中，并单独标记为 `no_usage`（无用量）。命令行可用 `--no-include-usage` 明确关闭采集，关闭后两种命中率都显示为不可得。
- 默认“冒烟”请求会为每条样本加入唯一编号，保证请求之间可区分，因此不会主动构造可复用的稳定缓存前缀；这类运行出现 0% 可能是上游真实返回的零缓存读取，不等于统计缺失。要测缓存能力，应使用重复的稳定长前缀并只改变末尾问题，再以 `usage`（用量）中的缓存字段核查。
- 选择“缓存压测”配置档（`--profile cache`）会发送固定长前缀，只轮换末尾问题；请求编号、时间戳和随机值不会进入前缀。该模式要求上游返回 `usage.cached_tokens`，并按 `cached_tokens > 0` 的请求数 ÷ 总请求数给出命中率。
- 每一条已实际开始的请求（包括失败、超时、响应不完整和取消）默认写入结果 JSONL（逐行 JSON）文件。记录包含任务与请求标识、状态码、错误类型、错误详情、原因、时间记录及用量字段；原始输入/输出仍需显式开启 `capture_raw`（原始正文记录），错误逐条核查不依赖原文开关。
- 页面只展示最近 100 条以控制内存，但每条失败记录保留请求标识和结构化错误详情；完整结果文件与导出用于核查全量请求。缓存命中请求率与 TPM 模块的缓存 Token（词元）读取比例是不同口径，不能互相替代。

具体价格、协议及运行步骤见 [使用说明](tpm.md)。`make benchmark-tpm`（长输入联合验证）使用真实长请求体和合成计数，覆盖持久化、查询及浏览器；不代表真实上游容量。

已完成请求的紧凑内存表示不改变任何计量字段：原始用量、未知与明确为零、缓存分类、逐请求时间及结算均保留。写入器复用同一编码正文，查询按需还原；实时指标只消费新增记录，即使已超过近期 100 条缓存也不重复或漏计。若编码失败，已经结算的请求继续计入费用和内存证据，立即停止新请求；该条不伪称落盘，报告保留原始计算值但标为证据不足，导出继续按实际文件完整性核查。

实时展示接口仅减少最近请求摘要中未展示的重复原始用量与结算快照，保留请求结果、阶段、全部已记录时间、输入输出及完整性。它不作为重新计算费用或判定的证据来源；默认详情、完整导出及历史记录保留所有字段。性能验证使用与浏览器相同的展示接口，额外核验视图标记；发送上游的请求体、观察频率、调度和判定阈值不因此减少。

新增运行的 `scheduling`（调度诊断）保存 `missed_by_reason`（按原因计数）和 `missed_by_stage`（分档原因计数）：调度迟到、并发容量已满、档位截止、主动停发、准入前停止、预算拒绝分别记录；尚无更细执行证据的剩余计划归为 `not_admitted`（未准入）。原因表示执行器实际采用的处理分支，调度迟到不能直接推断为某个网络或处理器故障。旧记录没有原因数据时保持未知，不倒推补造。

本地性能工具同时检查原有 5% 速率偏差，以及报告冻结的全程和目标档错过比例不超过 1%；还核对逐时隙证据、原因总账和判定阈值未变化。每 10 秒缺失分布、查询耗时及开始间隔随结果保存；开始间隔用单调调度延迟还原，墙钟与单调证据不一致时标记不可确定并阻止验收通过。

正式请求额外保存 `signed_schedule_delay_seconds`（未截断的实际开始相对时隙时差）与 `stage_deadline_margin_seconds`（准入时距原档位截止的剩余秒数）。两者采用同一单调时刻，校准没有固定时隙时为空。本地联测要求前者不小于零、后者严格大于零，并逐条对照冻结计划；不以取零掩盖提前发送，不放宽档位截止。截止前已启动、截止后完成的请求正常收尾，完成量仍按原观察窗口归属。新任务的正式报告逐条比对墙钟开始／结束与单调时间投影，偏差超过 5 毫秒或证据缺失时将主窗口标为不可核验，结论为证据不足；原时间、用量和比例保留供追溯，不重新分配请求到其他窗口。规则在预览中展示并随计划冻结。缺少独立时间证据的旧历史明确标为未知，不声称按新标准核验。

可选 `--diagnostics`（运行诊断）仅在隔离的本地模拟服务中采集垃圾回收、详情快照、历史保存和响应序列化耗时。原粗边界保留全部调用汇总，新增频繁的小边界仅统计至少 2 毫秒的慢调用，不能把其计数当全部调用次数；保留有界慢事件。定时回调、睡眠恢复与请求入口采用预分配的 0.1 毫秒直方图，输出分位数所在范围，详细迟到事件至少 5 毫秒才保存；这些分桶仅用于诊断，产品百分位仍使用精确统计，所有验收阈值不变。时间点使用新加坡时间，同时保存单调时间与线程编号；只读取必要的时间数值和正式阶段标记，不采集正文、返回内容或凭据，不改变垃圾回收设置。探针本身有包装、时钟及上下文开销，结果须与关闭探针的完整阶梯区分；时间重叠不能单独证明唯一因果，包装耗时也不能直接当作处理器占用。

本地性能验证另保存 `observation.json`（阶段观测）：在原每两秒的进程内存采样前后夹读墙钟、单调时间和可用的原始连续时间，保存读取跨度、内存数值及最近响应的阶段与计数；缺失保持未知。阶段上下文可能在读取期间变旧，跨档或收尾须用完整单调区间核查，不能只凭上下文字段归因。完整导出前后仅保存时钟标记，不增加内存采样或混入旧峰值。采样失败、溢出或保存失败会使新增证据完整检查失败，原判定不变。

`--sparse-diagnostics`（稀疏诊断）与完整诊断互斥，只对每第 32 次睡眠、正式请求入口与当前选择器调用读时钟；跳过路径直接委派原操作，回收回调仍全量，频繁的快照和历史等边界不包装。采样总数、选中数、跳过数和比例逐项保存，直方图和十秒桶明确为抽样范围；不能把它们标为全量精确百分位。普通运行不加载诊断探针，正式产品百分位和全部验收规则不变。

系统日历校时可能造成渐进偏差或直接阶跃；新加坡时区只规定记录和显示方式，不等于墙钟已与单调时间同步。超出原 5 毫秒证据线仍阻止分钟窗口验证，不自动校时、不重写时间、不移动窗口。选择器调用观测包含解释器和线程交接，不能直接当作纯内核等待；睡眠、迟到及嵌套回收区间不得相加冒充处理器耗时。

## 原有模块

- 新建缺省压力为并发上限 20、RPM（每分钟请求数）100，适用于网关、压力对照、路由每侧和模型指纹；并发是同时在途上限，不代表实际同时发出 20 条。质量评测保持串行协议，没有这两个压力参数；历史复测保留原冻结值。
- 计划调度速率：计划每分钟开始多少请求；不是实际完成吞吐。
- 实际完成吞吐：客户端单位时间收到的最终结果数量；与服务端容量不等价。
- TTFT（首字耗时）：从本次请求开始到收到首个真实正文内容的单调时钟耗时；不能把心跳或空片段当正文。非流式响应不可观测，保持为空。
- p95（第 95 百分位）：95% 的被统计观测值不高于该值；不表示 95% 置信度。
- 质量评测：按冻结题集和判分规则计算。本轮未增加默认请求量；当前单轮结果不承诺跨次稳定性。
- 路由对照：按同一请求编号配对，交替两侧入队先后。网络到达先后不可用于验证调度公平性。
- 缓存命中：仅使用上游明确返回的用量字段；缺失用量不能当作未命中。
- 模型指纹：比较固定协议下的回答分布；不同提示、采样参数、调度速率或适配器的记录不能直接混比。新协议默认每分钟最多开始 100 请求，调度滞后不积累额度突发补发。旧协议缺少速率字段时沿用原并发工作池，不自动补入新速率。参考指纹需由使用者确认来源。保留思考采用独立版本、4096 词元硬上限（含推理与正文）、不传采样参数，只统计最终正文；当前仅展示探索性距离，不套用直接回答协议的判定阈值。选择和复测均披露单次及全计划上限后重新确认费用。

`make benchmark` 输出本机模拟接口与请求引擎的联合基线，包含操作系统、解释器版本、并发、请求数和延迟。它不包含真实模型推理、长流式响应及完整工作台持久化成本，不能宣称是网关或压测机的绝对容量上限。
